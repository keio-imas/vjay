# Video validation — 2026-11-18

Apple M2 Pro, Metal, macOS, installed FFmpeg. Input: the user-supplied 3840×2160
H.264 High 4:2:2 / yuv422p10le MOV, 24000/1001 fps, 243 frames, 10.116958 s.
The source was only read. The original path and track metadata are omitted here.

The old adapter failed with `failed to fill whole buffer`. Captured FFmpeg diagnostics
showed VideoToolbox callbacks returning `-12909` and a decoder error-rate exit.

The new adapter uses a ProRes 422 HQ cache, encoded through VideoToolbox with
software encoding disallowed. The first experimental cache took about 6.4 s and
occupied 810,124,281 bytes. Initial reading of the unsupported source uses CPU
decoding. Playback decodes and scales through VideoToolbox; RGBA conversion and
transport to wgpu still use CPU memory.

These are individual debug-test runs, not GPU timestamp measurements or a claim of
maximum rendering FPS. They measure the decoder port under 60 Hz realtime requests,
including one natural loop. The input rate predicts about 288 frames in 12 s.
Additional exact delivery seeks near the end, backwards, and to zero passed.
The final Release headless patch using Video → Transform → Output, with a
36,000,000-degree Rotation value and disconnected external service nodes, also
completed 730 frames at 3840×2160. The reported render loop plus final readback
took 4738.36 ms after warm-up (checksum `81dba8bad39bfeed`). Source SHA-256, size,
and modification time matched before/after. This whole-program result is distinct
from the decoder-only realtime measurements above.

Generated 4K H.264 8bit and HEVC Main10 sources passed direct VideoToolbox decode
and GPU-scale tests without a compatibility cache. Native GPU tests verified range
looping, holding the final frame, and a 36,000,000-degree Transform edit without
reopening the video decoder. Audio tests exercise the real CPAL callback with zero
gain and confirm ongoing sample consumption under Position modulation.

Reproduce the decoder test with a local source:

```sh
VJAY_TEST_VIDEO=/path/to/4k.mov VJAY_TEST_EXTENT=3840x2160 \
  cargo test -p vjay-infrastructure --test hardware_video gpu_video_keeps_up \
  -- --ignored --nocapture
```

Explicit seeks and subrange wraps still restart FFmpeg and can take preparation
time. Longer sets, simultaneous eight-source 4K playback, HDR output, and native
zero-copy VideoToolbox texture import were not validated by these measurements.
